反転パズルを作るときの考え方｜「ぜんぶつけて」から学ぶ状態とテスト

ルドット編集部 ／ 公開・確認：2026年11月13日

小さなパズルを作るとき、最初からきれいな画面や大量のステージを用意する必要はありません。まず「1回押したら、どのマスがどう変わるか」を決めると、動作確認の見通しがよくなります。ルドットの『ぜんぶつけて』を例に、反転パズルを設計するときの考え方を整理します。

対象はJavaScriptの配列や関数を少し読める、ゲーム制作を始めたい方です。ここに載せるコードは説明用に新しく書いた最小例で、公開ゲーム全体の複製や、完成した投稿作品ではありません。

盤面の表し方端の扱い確かめる性質問題の作り方完成前の確認

絵を描く前に、状態を小さく表す

通常の＋マスだけなら、5×5の盤面を25個の値で表せます。消灯を0、点灯を1に決め、画面はその配列を読み取って描きます。色やアニメーションを変更しても、盤面を動かす関数は変えずに済むように分けます。

下の例は、押したマスと上下左右を反転させます。元の配列を直接書き換えずコピーを返すので、操作前の状態を取っておけば「戻す」の比較にも使えます。実際の作品には穴・✕・わっかマスがありますが、この例では扱いません。

function pressPlus(board, row, col) {
  const next = board.slice();
  const offsets = [[0, 0], [-1, 0], [1, 0], [0, -1], [0, 1]];
  for (const [dr, dc] of offsets) {
    const r = row + dr;
    const c = col + dc;
    if (r < 0 || r >= 5 || c < 0 || c >= 5) continue;
    const i = r * 5 + c;
    next[i] = 1 - next[i];
  }
  return next;
}

この関数の前提は「25要素、値は0か1、行と列は0〜4」です。外部から値を受け取る完成版では、入力がこの範囲に収まるかも検証します。

右端の次を、次の行の左端にしない

一次元の配列では、位置4の次は位置5です。しかし盤面では、位置4は一番上の行の右端、位置5は二行目の左端です。単に番号へ1を足すと、右端から次の行へ回り込む誤動作になります。上の例では行と列で境界を確かめてから配列の番号に戻しています。

押す位置変わる数確認する失敗
中央（行2・列2）5個自分自身を忘れて4個になっていないか
上辺（行0・列2）4個存在しない上のマスを書き換えていないか
左上角（行0・列0）3個左への操作が前の行へ折り返していないか

正解の盤面より先に、変わらない性質を確かめる

反転には「同じ場所を2回押すと元に戻る」という性質があります。また、影響範囲が固定なら、Aを押してBを押した結果と、Bを押してAを押した結果は同じです。最初から全ステージの答えを用意しなくても、この2つで実装の間違いを探せます。

const start = Array(25).fill(1);
const once = pressPlus(start, 2, 2);
const twice = pressPlus(once, 2, 2);
console.assert(JSON.stringify(twice) === JSON.stringify(start));
console.assert(start.every(value => value === 1));

最後の行の確認は、元の盤面を壊していないことを見るためのものです。この記事の例では、25か所それぞれの二重押しと、全625組の押す順序、中央・辺・角の反転数を確認しました。これは説明用関数の試験で、公開ゲームの全操作を保証するものではありません。

公開ゲームでは盤面をビットで持ち、排他的論理和を使って反転しています。25マスの基本動作を理解する段階では、配列の0と1で十分です。ビット演算を学ぶときはMDNの排他的論理和の説明も参照してください。

解ける問題は、完成形から逆に作れる

25個すべてを点灯させた状態から、何か所か押して問題の盤面を作ります。もう一度同じ場所を押せば元へ戻るので、少なくとも一つの解き方を持つ盤面になります。公開ゲームの問題生成も、この考え方から出発しています。

ただし、問題を作るときに5回押したからといって「最小5手」とは限りません。同じ場所を2回押した分が打ち消されたり、別の短い組合せで解けたりするからです。『ぜんぶつけて』は別の解法探索で手数を調べています。自分の試作品で探索を実装していない間は、「最小手数」と断定せず「今回の目標手数」と分けて表示すると、遊ぶ人に誤解を与えません。

完成前は、操作・区切り・保存を別々に試す

  • 操作：タッチ1回が2手にならないか、マウスとキーボードで同じマスを選べるか。
  • 区切り：クリア後の追加入力を受け続けないか、やり直しで手数や表示が初期状態へ戻るか。
  • 戻す：盤面と手数を一緒に戻すか。ヒント利用の扱いもルールとして決めておく。
  • 保存：途中盤面を残すのか、クリア結果だけかを決め、保存できない環境でも画面が壊れないか。
  • 素材：自分で作ったものか、公開に必要な利用条件を満たす素材かを確認する。

制作の考え方をゲームで確かめたい方はぜんぶつけての攻略ノートへ。投稿するときは投稿ページのルールを確認してください。説明用の断片だけではゲームとして遊べず、そのまま投稿できる完成品ではありません。
